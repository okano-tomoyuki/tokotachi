# 0010. ウィジェットは保持型(retained mode)のツリーとし、イベントループは待機型で、変化した領域だけを描き直す

- 状態: 承認
- 日付: 2026-10-04

## 背景

ゲームでよく使われる即時型(immediate mode。毎フレームすべてを描き直す)の GUI は書きやすいが、
何も変化が無いときも CPU・GPU を使い続け、ノート PC のバッテリーや aarch64 の機器で不利になる。
Qt と同じ種類の、業務アプリケーション向けの GUI ライブラリを目指すので、変化が無いときは何もしないことが望ましい。

## 決定

- **ウィジェットは保持型のツリーにする**。ウィジェットは状態(位置、大きさ、テキスト、選択など)を持ち、
  状態が変わったときに自分の領域を無効にする(invalidate)。
- **イベントループは待機型にする**。`SDL_WaitEvent`(タイマーがあるときは `SDL_WaitEventTimeout`)でイベントが来るまで眠り、
  溜まったイベントをすべて処理してから、無効になった領域があれば描く。
- **描くのは無効になった領域だけにする**。領域をクリップして、その領域に重なるウィジェットだけを描き直し、
  テクスチャの転送もその領域に限る。CPU で描く([ADR 0006](0006-plutovg-cpu-rendering.md))ことの前提になる。
- **Windows のウィンドウのリサイズ中も描く**。Windows は、ウィンドウの枠をドラッグしているあいだ OS のモーダルループに入り、
  `SDL_WaitEvent` に戻ってこない。その間も `SDL_EVENT_WINDOW_EXPOSED`(`data1 == 1`)がメインスレッドの event watch
  (`SDL_AddEventWatch`)に届くので、そこでレイアウトと描画を行う。
- **他のスレッドからの依頼**は、`SDL_RunOnMainThread` か `SDL_PushEvent` でメインスレッドに渡す(ウィジェットはメインスレッドだけで扱う)。

## 影響

- 技術検証(`spike/m1`)は、待機型のループと event watch の描画を実装した(ただし毎回ウィンドウ全体を描き直す)。
  Windows のリサイズ中の描画はまだ目視で確かめていない。
- キャレットの点滅・アニメーションはタイマーで必要なときだけループを起こす。動いているものが無ければ眠ったままにする。
- Wayland では、描画の頻度をコンポジタの frame callback に合わせる必要があるかを、SDL3 の `SDL_Renderer` の振る舞いを見て確かめる。
