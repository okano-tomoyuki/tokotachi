# 0007. テキストは HarfBuzz + FreeType を直接使い、レイアウト・フォールバック・IME の表示は自前で持つ

- 状態: 承認
- 日付: 2026-10-04

## 背景

Qt に匹敵する品質を目指すうえで、最も工数がかかるのがテキストである。必要なものは次のとおり。

- シェーピング(カーニング、合字、結合文字、縦書きは当面対象外)
- ラスタライズとグリフのキャッシュ
- 改行(日本語の禁則を含む)、双方向テキスト(アラビア語・ヘブライ語)
- フォントのフォールバック(日本語のフォントに無い文字・絵文字)とシステムのフォントの探索
- 編集のための情報: キャレットの位置、文字の選択、マウスの位置から文字の位置へのヒットテスト、IME の変換中の文字列の表示

## 検討した選択肢

- 選択肢A: SDL_ttf 3 を使う。HarfBuzz を内蔵し、折り返しも持つが、編集のための情報(ヒットテスト、選択、
  クラスタの境界)と描画先の制御が足りず、エディタ系のウィジェットには向かない。
- 選択肢B: HarfBuzz(シェーピング)+ FreeType(ラスタライズ)を直接使い、その上のレイアウトは自前で持つ。

## 決定

**選択肢B を選ぶ。** 層は次のように分ける。

| 層 | 内容 | 使うもの |
|---|---|---|
| FontDB | システムのフォントの探索、フォールバックの順序 | Linux は fontconfig、Windows は Fonts フォルダ(将来 DirectWrite のフォントの列挙も検討) |
| Shaper | 1 つのフォント・1 つの方向・1 つの文字体系の連続(run)のシェーピング | HarfBuzz |
| Layout | run への分割(フォールバック・双方向)、改行、行の配置、ヒットテスト、キャレット・選択の位置 | SheenBidi(双方向)、libunibreak(改行)を予定 |
| GlyphCache | グリフのラスタライズとキャッシュ | FreeType(グレースケール) |

- 双方向テキストは SheenBidi(Apache-2.0、CMake でビルドできる)を使う。FriBidi は Meson のみなので使わない([ADR 0005](0005-build-dependencies-from-source.md))。
- 改行は libunibreak(zlib)を使う。autotools のみなので、ソース(C の数ファイル)を自前の CMake でビルドする。
- テキストの位置はすべて UTF-8 のバイトの位置で表す(HarfBuzz の cluster と同じ)。

## 影響

- 技術検証(`spike/m1`)で、日本語・カーニング(`AVA To Ty`)・合字(`ffi fl`)を描けることを確かめた。
- 検証のコードはガンマ補正をせずに合成しているため、OS の描画(DirectWrite など)より細く見えることがある。
  → 被覆率の補正で改善した([ADR 0020](0020-bidi-and-text-rendering-quality.md))。
- サブピクセルの位置決め(グリフの横の位置を 1/4 ピクセル単位でキャッシュする等)は、品質と性能を見て後で決める。
  → 1/4 ピクセル単位で入れた([ADR 0020](0020-bidi-and-text-rendering-quality.md))。改行・双方向テキストは [ADR 0019](0019-line-breaking-and-text-navigation.md)・0020。
- 絵文字(カラーのグリフ: COLR・CBDT・sbix)は当面対象外とし、FontDB・GlyphCache の設計で余地を残す。
