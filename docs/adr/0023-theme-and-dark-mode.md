# 0023. テーマはアプリケーションが 1 つ持ち、色は役割か具体的な色で指定する。ライト・ダークは既定で OS の設定に従う

- 状態: 承認
- 日付: 2026-10-04

## 背景

標準のウィジェットの色と寸法は、内部の `theme.hpp` に固定の値で置いていた(仮置き)。ウィンドウの背景・ツールチップ・`Label::color` の既定値も、
具体的な色を直接書いていた。このままでは、ダークモードにできず、利用者がアクセントの色などを変えることもできない。

決めること:

- テーマをどの範囲に効かせるか(アプリケーション全体か、ウィンドウ・ウィジェットごとに継承させるか)。
- `Label::color` のような色のプロパティとテーマの関係(テーマを切り替えたら変わるのか)。
- ライト・ダークの既定。

## 検討した選択肢

適用の範囲:

- 選択肢A: アプリケーションが 1 つのテーマを持ち、すべてのウィンドウに効かせる。部分的な変更は、ウィジェットの色のプロパティで行う。
- 選択肢B: ウィンドウ・ウィジェットにテーマを設定でき、設定しない子は親のものを継承する(Qt の palette、CSS に近い)。
  柔軟だが、どのテーマが効いているかを辿る仕組みが要り、切り替えたときに描き直す範囲も複雑になる。

色のプロパティ:

- 選択肢A: 役割(`ColorRole`)か具体的な色(`Color`)のどちらかを持つ値(`ThemeColor`)にする。役割で指定した色は、テーマを切り替えると変わる。
- 選択肢B: `Color` のままにし、既定値だけテーマから取る。一度代入するとテーマを切り替えても変わらず、控えめな文字のような色をダークに合わせるには、
  利用者が切り替えを自分で処理する必要がある。

ライト・ダークの既定:

- 選択肢A: OS の設定に従う(分からなければライト)。
- 選択肢B: 既定はライトにし、アプリケーションが指定したときだけ変える。

## 決定

**いずれも選択肢A を選ぶ。**

### テーマ(`Theme`)

- 値の型。24 の役割(`ColorRole`)ごとの色と、寸法(`radius`・`field_radius`・`field_padding`)、暗い組み合わせかの目安(`dark_colors`)を持つ。
  色は `theme[ColorRole::ACCENT]` で読み書きする。
- 標準は `Theme::light()`・`Theme::dark()`。利用者はこれを写して一部を変え、アプリケーションに渡す。

### アプリケーション

- `color_scheme`(`SYSTEM`・`LIGHT`・`DARK`。既定は `SYSTEM`)、`light_theme`・`dark_theme`(既定は標準のもの)。
- 読み取り専用の `dark`(今ダークか)・`theme`(今使っているテーマ)。結びつけ([ADR 0016](0016-property-binding.md))の元にもできる。
- `SYSTEM` のときは `SDL_GetSystemTheme` で OS の設定を読み、`SDL_EVENT_SYSTEM_THEME_CHANGED` が届いたら読み直す。
- 使うテーマが変わったら、`dark`・`theme` の変更を知らせ、すべてのウィンドウで、ウィジェットに `theme_changed()`(protected の仮想関数)を送り、
  配置をやり直す印を付け(寸法が変わりうるため)、全体を描き直す。最後に `on_theme_change` を呼ぶ。

### 色の指定(`ThemeColor`)

- 役割か具体的な色のどちらか。`Color` からも `ColorRole` からも暗黙に作れるので、`label->color = ColorRole::TEXT_SECONDARY;` と
  `label->color = Color::rgb(0xdc2626);` のどちらも書ける。`resolve()` で今のテーマの具体的な色にする。
- `Label::color`(既定は `TEXT`)・`Window::background`(既定は `WINDOW`。ポップアップは `POPUP`)を `ThemeColor` にした。
  ツールチップは `TOOLTIP`・`ON_TOOLTIP` を使う。

### 標準のウィジェット

- 色・寸法は描くたびに今のテーマから読む(キャッシュしない)。テーマを切り替えたら、描き直すだけで変わる。

## 影響

- `Label::color`・`Window::background` の型が `Property<Color>` から `Property<ThemeColor>` に変わった。`Color` の代入はそのまま書ける。
  読むときは `.get().resolve()` で具体的な色にする。
- アプリケーションが `DARK` を指定しても、Windows のタイトルバー(OS が描く枠)は OS の設定に従ったまま(SDL3 が OS の設定で合わせる)。
- WSLg・ヘッドレス(offscreen)では OS の設定が分からないことが多く、そのときは `SYSTEM` でもライトになる。
- テーマを切り替えると、どのウィジェットも描き直す。ウィンドウの数・大きさに比例するが、切り替えは稀なので問題にしない。
- ウィンドウ・ウィジェットごとのテーマ(継承。後に [ADR 0042](0042-widget-theme-override.md) で一部の上書きを加えた)、フォントをテーマに含めること、ハイコントラストへの対応は対象外(必要になったら別の ADR で決める)。
