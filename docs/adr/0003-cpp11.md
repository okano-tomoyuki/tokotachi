# 0003. C++11 で書き、公開のヘッダは C++20 でもコンパイルできるようにする

- 状態: 承認
- 日付: 2026-10-04

## 背景

bethany・cpp_tk と同じく、広い開発環境で使えるようにしたい。C++17 以降の機能(`std::string_view`、`std::optional`、
`std::variant`、`std::filesystem`、`if constexpr` など)を使うと、古いコンパイラ・ディストリビューションで使えなくなる。

依存ライブラリの公開の API は、C++11 で使えることを確かめた。SDL3・FreeType・HarfBuzz・plutovg はいずれも C の API で、
`-std=c++11 -pedantic` で警告なくコンパイルできる。各ライブラリの内部は別の規格でビルドしてよい
(依存ライブラリは別にビルドする。[ADR 0005](0005-build-dependencies-from-source.md))。

## 検討した選択肢

- 選択肢A: C++17 で書く。書きやすいが、対象の環境が狭まる。
- 選択肢B: C++11 で書き、足りない部品は自前で用意する。

## 決定

**選択肢B を選ぶ。** 技術的に実現が難しい、または性能を著しく損なうことが分かった場合に限り、C++17 に上げることを検討する。

C++17 の部品は、必要に応じて次のように補う。

| C++17 の部品 | 代わり |
|---|---|
| `std::string_view` | 自前の `StringView`(ポインタと長さ)。テキストの処理で部分文字列のコピーを避けるために要る |
| `std::optional` / `std::variant` | 簡易版を自前で用意するか、設計で避ける |
| `std::make_unique` | 自前の 1 行の関数 |
| `std::filesystem` | SDL3 の `SDL_GetBasePath`・`SDL_GlobDirectory`・`SDL_IOStream` |
| `std::wstring_convert`(C++17 で非推奨) | UTF-8・UTF-16・UTF-32 の変換を自前で持つ(テキストの処理で必要になる) |

利用者が新しい規格でビルドしても壊れないよう、公開のヘッダでは次のものを使わない。

- `u8"..."` のリテラル(C++20 で型が `char8_t` に変わる)。ソースは UTF-8 で書き、普通のリテラルを使う。
- `std::result_of`(C++20 で削除)、`std::iterator` の継承(C++17 で非推奨)、`[=]` による暗黙の `this` のキャプチャ(C++20 で非推奨)。

## 影響

- CI では `-std=c++11` と `-std=c++20` の両方でビルドする。
- 警告は `-Wall -Wextra -pedantic` で出ない状態を保つ。
- スレッドは `std::thread`・`std::mutex` を使ってよい(MSYS2 の MinGW は POSIX のスレッドのモデルで、`-static` で winpthread も含められる)。
