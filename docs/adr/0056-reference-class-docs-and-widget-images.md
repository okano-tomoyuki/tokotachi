# 0056. リファレンスのクラスのページに説明と部品の画像を出し、クラスを分類(トピック)で引けるようにする

- 状態: 承認
- 日付: 2026-10-12

## 背景

Doxygen のリファレンス(docs/adr/0038)では、部品の説明とコード例を各ヘッダの先頭の `@file` に書いていた。そのため、`Button` などの
クラスのページには継承の図とメンバの一覧しか出ず、何の部品かが分からなかった(説明の無いクラスが 69 個)。説明は「詳解」として
ページの一番下に出る既定の並びだった。クラスはアルファベット順の一覧でしか引けず、部品の見た目はサンプルの一覧のページにしか無かった。

## 決定

- **クラスの説明**: 1 つのクラスを宣言するヘッダは、`@file` の説明とコード例をクラスの説明に移し、`@file` には
  「tokotachi::Button の宣言。」だけを残す。複数のクラスを宣言するヘッダ(geometry・event・canvas・property など)は、説明の無かった
  クラスに短い説明を書く。
- **ページの並び**: `docs/DoxygenLayout.xml`(`doxygen -l` の既定から変える)で、クラスの説明(詳解)を継承の図の後、メンバの一覧より前に
  出す。トピックのページの詳解は概要と同じなので出さない。
- **分類(トピック)**: `docs/guide/topics.dox` の `@defgroup` で、ディレクトリと同じ 7 つ(core・graphics・layout・widgets・windows・
  actions・views)に分け、core は「オブジェクトとプロパティ・イベント・スレッド・基本の値」、widgets はデザイナーのパレットと同じ
  「入力・表示・入れ物・描画・部品の基底」に分ける。公開のクラス(93 個)すべてに `@ingroup` を付ける。
- **部品の画像**: `docs/widget_images.cpp` が部品を 1 つずつ小さなウィンドウに置き、ライトのテーマで描いて `widget_<名前>.png` にする
  (リファレンスを作るとき、cmake の docs のターゲットで画面なしで動かす。メッセージのダイアログは開いて撮る)。部品のクラスの説明の
  最初の段落の後に `@image html` で載せる(Window・ColorDialog はサンプルの一覧の画像を使う)。
- **手引き**: トップページの手引きの表を `@subpage` にして、左の目次で手引きのページを決まった順に並べる。API リファレンスの節に分類への
  リンクを加える。
- **ロゴ**: 見出しのロゴとブラウザのタブのアイコンに、デザイナーの拡張のアイコン(docs/adr/0055)を使う(`PROJECT_LOGO`・`PROJECT_ICON`)。
  リポジトリの README の見出しにも載せる。

## 影響

- 新しい公開のクラスを足したら、クラスに説明と `@ingroup` を書き、部品なら `docs/widget_images.cpp` に撮り方を足して `@image html` で載せる。
- 暦(Calendar)の画像は撮った日の「今日」に輪が付くので、リファレンスを作るたびに少し変わる。
- メンバの説明の無いもの(上書きした仮想関数・演算子・コンストラクタなど)は今回は対象外。
