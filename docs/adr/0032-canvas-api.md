# 0032. Canvas は利用者が描くための公開の API とし、決まりを明文化して、変換・線の形・パスのクリップ・手軽な関数を加える

- 状態: 承認
- 日付: 2026-10-04

## 背景

C++Builder の TCanvas のように、利用者が自由に描ける API が要る。Canvas([ADR 0006](0006-plutovg-cpu-rendering.md))は
ライブラリの部品が描くために作ったもので、公開のヘッダにあるが、利用者が使ってよいか・どう使うかを決めていなかった。
また、TCanvas と比べて、拡大・回転・破線・パスでのクリップ・手軽な関数などが足りなかった。

重い描画の扱い(画像への描画・別のスレッドでの描画)も合わせて検討し、次の順で進めることにした:
①Canvas の決まりの明文化と API の拡充(この ADR)→ ②書き換えられる画像(Bitmap)とそれに描く Canvas、PaintBox
→ ③フォントのキャッシュをスレッドをまたいで安全にし、別のスレッドで Bitmap に描けるようにする。

## 決定

### 立場と決まり

- **Canvas はウィジェットではなく「描く先」。** VCL の TCanvas(TPersistent の派生)と同じ立場で、画面に置く部品は Widget
  (on_paint を使う・paint を上書きする)。VCL の TPaintBox に当たる部品は②で用意する。
- Canvas は描画の呼び出し(paint・on_paint)の間だけ有効。参照を持ち続けない。描き直したいときは invalidate で頼む。
- メインスレッドからだけ使う(③で Bitmap に描く Canvas は別)。
- 座標は dp。描画はウィンドウの裏のバッファーに描いてから画面に出す(ダブルバッファリング)。
- 描く範囲はクリップされている。重い描画は clip_bounds() の外を飛ばす(一覧が見えている行だけを描くのと同じ)。

### 加えたもの

- 変換: `translate`・`scale_by`・`rotate`(save・restore で戻す)。`scale()` は既にある dp からピクセルへの倍率なので、
  拡大は `scale_by` とした。
- 線の形: `StrokeStyle`(太さ・端の形・角の形・破線とそのずらし)。`stroke_path(path, style, paint)` を基本の関数にした。
- クリップ: `clip_path(path)`(`clip_rect` に加えて)。
- Path: `quad_to`・`add_arc`(楕円の弧。円グラフなど)・`add_polyline`。
- 手軽な関数(基本の関数を組み合わせる。仮想関数ではない): `draw_line`・`stroke_rect`・`fill_ellipse`・`stroke_ellipse`・
  `draw_text(文字列, 位置, 色[, フォント])`・`stroke_path(path, 太さ, 塗り, 端)`。

### 描き方

- **変換が平行移動だけで、クリップが矩形だけのときは、これまでどおり矩形の辺をピクセルに揃え、文字はヒンティングした
  グリフのビットマップで描く**(にじまない・速い)。
- 拡大・回転があるとき、パスでクリップしているときは、ピクセルに揃えず、文字はグリフの輪郭(FreeType から取り出し、
  フォントの実体ごとに覚える)をパスとして塗る。グラデーション・画像の模様は、変換を行列として plutovg に渡す。
- 線の太さ・破線の長さは、変換の拡大の大きさ(行列の行列式の平方根)を掛ける。

## 影響

- 拡大・回転した文字はヒンティングしないので、少し柔らかく見える。カラーの絵文字(輪郭の無いビットマップのグリフ)は
  拡大・回転したときに描かない。
- 画素の直接の読み書き、画面以外への描画は②で扱う。
- GPU での描画は対象外。Canvas は抽象クラスなので、将来の実装の差し替えはできる。

## 後の変更

- Canvas は仮想関数を持たない具体的なクラスにし、実際の描画は内部の描画先(`Canvas::Impl`)に任せた。描画先の差し替えは、
  これまでどおりライブラリの中でできる([ADR 0060](0060-canvas-without-virtual-functions.md))。
