# 0011. メニュー・ドロップダウン・ツールチップは、親のウィンドウに相対的なポップアップのウィンドウとして作る

- 状態: 承認(実装と検証の詳細は [0022](0022-popups-combo-box-menu-tooltip.md))
- 日付: 2026-10-04

## 背景

メニュー、コンボボックスのドロップダウン、ツールチップは、親のウィンドウの外にはみ出して表示する必要がある。
X11・Windows では、トップレベルのウィンドウを画面の絶対座標に置けばよかった。

Wayland では、クライアントは画面の絶対座標を知らず、トップレベルのウィンドウの位置も指定できない([ADR 0002](0002-target-platforms-and-wayland-first.md))。
親のウィンドウの外に出る表示は xdg_popup で作るしかなく、位置は親のウィンドウからの相対で指定し、
画面からはみ出すときの調整(反転、ずらし)はコンポジタが行う。メニューのようにキーボード・マウスを専有する(grab する)ポップアップは、
入力のイベントを起点にしないと作れない。

## 検討した選択肢

- 選択肢A: 親のウィンドウの中に描く(ウィンドウの外にはみ出せない)。どの環境でも動くが、小さいウィンドウでメニューが切れる。
- 選択肢B: SDL3 の `SDL_CreatePopupWindow`(`SDL_WINDOW_POPUP_MENU`・`SDL_WINDOW_TOOLTIP`)で作る。
  Wayland では xdg_popup、Windows・X11 では親に相対的な位置に置いたトップレベルのウィンドウになる。

## 決定

**選択肢B を選ぶ。** ポップアップは、親のウィンドウ(またはポップアップ)からの相対の位置(dp)で作る API にする。

- メニューとドロップダウンは、マウスのボタン・キーの押下を処理している中で開く(タイマーや非同期の処理から開かない)。
- 画面からはみ出すときの位置の調整は、Wayland ではコンポジタに任せる。Windows・X11 では SDL3 が行う調整に任せる。
- ポップアップの中の描画・イベントの処理は、通常のウィンドウと同じ仕組み([ADR 0010](0010-retained-mode-and-event-loop.md))で行う。

## 影響

- 状態は「提案」とする。ポップアップを実装する段階で、Wayland(実機)・Windows・X11 で、位置、grab、入れ子のメニュー、
  フォーカスの戻り方を確かめてから「承認」にする。
- ポップアップの位置を画面の絶対座標で指定する API は提供しない。
