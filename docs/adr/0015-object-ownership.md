# 0015. すべての Object が所有者を持てるようにし、ウィジェットの親は所有者を兼ねる

- 状態: 承認
- 日付: 2026-10-04

## 背景

ウィジェットは親が子を所有する([ADR 0012](0012-ownership-and-naming.md))が、ウィジェット以外の Object(Timer、
これから加える Variable 等)には所有の仕組みが無く、`new` で作ったものは利用者が `delete` する必要があった([ADR 0014](0014-timer.md))。

ウィジェット・タイマー・変数を「すべて `new` で作り、所有者に任せる」という一貫した書き方にすると、利用者が迷いにくく、
デザイナーのコード生成も単純になる。

## 決定

- **`Object` のコンストラクタは `Object* owner` を受け取る**(既定は nullptr)。所有者が破棄されるときに、所有しているオブジェクトも破棄される。
  所有者は読み取り専用のプロパティ `owner` で読める。
  ```cpp
  tokotachi::LineEdit* edit = new tokotachi::LineEdit(&window);              // ウィジェットは親が所有者を兼ねる
  tokotachi::Timer* timer = new tokotachi::Timer(&window);
  tokotachi::StringVariable* name = new tokotachi::StringVariable(&window);
  ```
- **所有者が nullptr のオブジェクトは利用者が寿命を管理する**(スタック・メンバ変数にも置ける)。所有者を持つオブジェクトをスタックに置くと
  二重に破棄されるので、置いてはいけない(ウィジェットと同じ制約)。
- 先に破棄したオブジェクトは、所有者の一覧から外れる。
- **ウィジェットの親子(表示のツリー)は、所有とは別に Widget が持つ**。Widget のコンストラクタは親を所有者として `Object` に渡すので、
  ウィジェットでは親と所有者が常に一致する。ウィジェット以外のオブジェクトは表示のツリーに入らない。
- 派生クラスのデストラクタは、自分がまだその型であるうちに `delete_owned()` で所有しているオブジェクトを破棄できる
  (Widget・Window はそうしている。子のデストラクタが親のウィジェットの状態に触るため)。呼ばなければ `Object` のデストラクタが破棄する。
- 所有者の付け替えは、ウィジェットの親の付け替えとしてだけ扱う([ADR 0018](0018-reparenting.md))。

## 影響

- [ADR 0014](0014-timer.md) の「`new Timer` は利用者が `delete` する」という制約が無くなる(所有者を渡せばよい)。
- 破棄の順番: ウィンドウを破棄すると、ウィジェット・タイマー・変数などの所有しているオブジェクトが、ウィンドウがまだ Window であるうちに
  破棄される。

## 後の変更

- 所有者を渡さずに作ったトップレベルのウィンドウは Application が所有し、所有者のウィンドウを渡して作ることもできるようにした。
  Object から派生したものは new で作り、スタックに置くのは Application だけにする書き方に揃えた([ADR 0062](0062-window-ownership-and-quit.md))。
