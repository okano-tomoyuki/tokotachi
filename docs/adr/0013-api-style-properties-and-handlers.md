# 0013. 公開の API はプロパティと単一のハンドラで表し、命名と書式の規則を定める

- 状態: 承認
- 日付: 2026-10-04

## 背景

[ADR 0012](0012-ownership-and-naming.md) で土台の層を作ったところ、API が Qt に近くなった(`set_text()`・`text()` の組、
複数の関数をつなげる `Signal`、`paint_event` 等の名前)。

このライブラリは独自の実装であり、Qt に限らず特定の GUI フレームワークに寄せない。Qt・bethany(LCL / C++Builder)・
cpp_tk(Tk)・その他のフレームワークを参考にしつつ、良いところを集める。

その観点で、ウィジェットの状態の読み書きとイベントのハンドラの設定は、bethany で培ったプロキシ(`Property<T>`)の方が
自然に書ける(`label->text = "..."`、`button->on_click = ...`)。

## 決定

### 全体の方針

- 特定の GUI フレームワークに寄せない。名前・API の形は、フレームワークの慣習ではなく、このライブラリの規則で決める。

### プロパティ

- `Object` の派生クラス(`Widget`・`Application` 等)の状態は、**プロパティだけ**で読み書きする。
  `set_xxx()` / `xxx()` のメソッドの組は作らない(同じことをする書き方が 2 つになるため。bethany の ADR 0022 と同じ考え方)。
  - 読み書きできるもの: `Property<T>`。読み取り専用のもの: `ReadOnlyProperty<T>`。
  - プロキシの形は bethany と同じ: 所有者(`Object*`)と、読み取り・書き込みの関数ポインタを持つ(ヒープの確保なし)。
    値は `T` への暗黙の変換か `.get()` で取り出す。プロパティ同士の代入は値のコピー、複合代入(`+=` 等)・`++`・`--`・
    ポインタ型の `->` を使える。`std::string` のプロパティは `+`・`==`・`!=` を `std::string` と直接組み合わせられる。
  - 状態ではない「操作」(`select_all()`・`close()`・`invalidate()` 等)と、引数を取る問い合わせ(`child_at(p)` 等)はメソッドにする。
  - 値の型(`Point`・`Rect`・`Color`・`Font`・`TextLayout`)とイベントの値(`MouseEvent` 等)は、プロパティを使わず、
    公開のメンバ変数とメソッドで表す。
- 位置と大きさは **`x`・`y`・`width`・`height`** と、それらをまとめた **`bounds`**(`Rect`)とする。

### イベントのハンドラ

- イベントは **単一のハンドラのプロパティ**(`on_xxx`)とする。代入で入れ替え、`nullptr` で解除する。複数の関数はつながない。
- ハンドラは **発生元(sender)を `Object*` で受け取る**。型は `NotifyHandler`(`void(Object* sender)`)、
  `MouseHandler`(`void(Object* sender, MouseEvent& e)`)など、すべて第 1 引数を `Object* sender` にそろえる。
  - Widget 以外の発生元(Timer・将来のメニューの項目やアクション)とも同じ型を使え、1 つのハンドラを種類の違う発生元で共有できる
    (bethany の `TNotifyEvent` の `TObject* Sender` と同じ)。
  - 発生元の機能を使うときは `dynamic_cast` で型を確かめる(`Object` は仮想デストラクタを持つ)。
  - マウス・キーのイベントは実際には Widget からしか来ないが、規則を 1 つにするため同じく `Object*` とする。
  - 採らなかった案: Widget の系統だけ `Widget*` にする(発生元の種類ごとにハンドラの型が増え、共有できない)。
    発生元の型で受ける(`on_click` を `void(Button*)` にする。継承したイベントだけ `Widget*` になってそろわず、
    プロパティ同士の代入もできなくなる)。
- 派生クラスのための入口は **動詞の名前の protected な仮想関数**(`paint`・`mouse_down`・`key_down`・`click` 等)とする。
  基底の実装がハンドラを呼ぶので、上書きする側は基底の実装を呼ぶ(呼ばなければハンドラは呼ばれない)。
- ハンドラはコピーしてから呼ぶ(ハンドラの中でハンドラを差し替えてもよいように)。ウィジェットは状態の更新を終えてからハンドラを呼ぶ
  (ハンドラの中でそのウィジェットが破棄されてもよいように)。
- マウスのボタン・キーのイベントは、受け取らなかったもの(`accepted = false`)が親のウィジェットへ送られる。
  基底の実装は、ハンドラがあれば呼び、無ければ `accepted` を `false` にする。

### 命名と書式

- クラス: PascalCase。メソッド・関数・公開のメンバ変数(プロパティを含む): snake_case。非公開のメンバ変数: 末尾に `_`。
- 定数: 大文字の snake_case。enum の値もすべてこれに当たる(`Key::BACKSPACE`、`MouseButton::LEFT`)。
- **マクロとぶつかる名前は別名にする**。`enum class` でもマクロの置き換えは防げない。例えば、利用者が先に `<windows.h>` を
  読み込むと `DELETE` が winnt.h のマクロに置き換えられるため、Delete キーは `Key::DEL` とする。
  大文字の名前に限らない。X11 の `<X11/X.h>` は `CursorShape` をマクロにしているため、マウスのカーソルの形の型は `MouseCursor` とする
  (下のテストで見つかった)。
  公開のヘッダは、Windows では `<windows.h>`、Linux では `<X11/Xlib.h>` の後に読み込んでもコンパイルできることをテストで確かめる。
- 書式はオールマンスタイル(波括弧を独立した行に置く)。インデントは空白 4 つ。リポジトリの `.clang-format` に定める。

## 影響

- [ADR 0012](0012-ownership-and-naming.md) のうち、所有(親が子を所有する)は引き継ぎ、命名の一部(メソッドの getter/setter)と
  シグナル(`Signal<Args...>`)は本 ADR で置き換える。
- プロパティ 1 つにつきポインタ 3 つ分(64 ビットで 24 バイト)を使う。ウィジェット 1 つにプロパティ・ハンドラが 30 個あれば
  約 720 バイトになる。大量の項目を表示するビュー(リスト・表)は、項目ごとにウィジェットを作らない設計にする。
- `Property<T>` を `auto` で受けるとプロキシのままになる、`printf` の可変長の引数に渡せない、などの制約は bethany と同じ
  (値が必要なら型を明示するか `.get()` を使う)。
- ライブラリの中でプロパティを定義するときは、内部のヘルパー(`src/core/property_impl.hpp`)で読み取り・書き込みの関数を作る。
  利用者が自分のウィジェットにプロパティを加えるときは、静的な関数を 2 つ書く(bethany と同じ)。
