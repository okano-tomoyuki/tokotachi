# 0033. 書き換えられる画像 Bitmap・描く部品 PaintBox・グループの透過(レイヤー)を加える

- 状態: 承認
- 日付: 2026-10-04

## 背景

[ADR 0032](0032-canvas-api.md) の②。重い描画を前もって描いておく・画素を直接扱うための、画面以外の描き先が要る。
また、VCL の TPaintBox に当たる名前の付いた部品が無く、Canvas と Widget の関係が分かりにくかった。
Color のアルファで図形ごとの半透明は描けるが、複数の図形をまとめて透過する(重なった所が濃くならない)ことはできなかった。

## 決定

### Bitmap

- 大きさ(ピクセル)と倍率(dp からピクセルへ)を決めて作る、書き換えられる画像。`canvas()` で画面と同じ Canvas の API で描け
  (座標は dp)、`pixel`・`set_pixel`(アルファを乗算していない色)と `pixels()`(アルファ乗算済みの ARGB の並び)で画素を読み書きできる。
- `to_image()` は画素を写した変更しない Image を返す(画面に貼る・別のスレッドから渡す)。`from_image()` で Image から作る(読み込んだ画像の編集)。
- コピーはできず、ムーブだけ(大きな画素の暗黙のコピーを避ける)。Bitmap の Canvas は Bitmap が生きている間有効。
- 1 つの Bitmap は同時に 1 つのスレッドからだけ使う。**文字を描けるのは、③(フォントのキャッシュをスレッドをまたいで安全にする)
  までメインスレッドだけ。**

### PaintBox

- `on_paint` で描く部品(VCL の TPaintBox)。普段は Widget に on_paint を付けるのと同じ。
- `cached` を true にすると、描いた結果を今の大きさ・倍率の Bitmap に描いて覚え、`refresh()` を呼ぶか、大きさ・倍率・テーマが
  変わるまで on_paint を呼ばない(画面の描き直しでは覚えた絵を貼るだけ)。

### グループの透過

- `Canvas::begin_layer(opacity)`・`end_layer()`。間に描いたものを、今のクリップの範囲だけの一時的な画像に描き、opacity で重ねる。
  入れ子にでき、begin_layer は save を、end_layer は restore を兼ねる。
- 実装: 描き先を一時的な画像に切り替え、plutovg には一時的な画像の左上の分の移動を行列で渡し(座標はいつも全体のまま計算する)、
  自前のグリフの合成ではその分を引く。重ねるときは元の描き先のクリップ(パスのクリップを含む)が効く。
- 加算・乗算などの重ね方の指定は対象外(必要になったら追加する)。

## 影響

- レイヤーの一時的な画像は begin_layer のたびに確保する。描画のたびに大きなレイヤーを使うと遅くなる。
