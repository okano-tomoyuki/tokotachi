# 0039. デザイナーを VS Code の拡張として本リポジトリに作り、キャンバスは WebAssembly にした Tokotachi で描く

- 状態: 承認
- 日付: 2026-10-10

## 背景

前作 Bethany には、VS Code の拡張としてデザイナー(画面の定義ファイル + コード生成)がある(Bethany ADR 0001・0035・0036・0065)。
Tokotachi でも、部品を置いてプロパティを設定するだけで画面ができる体験を用意したい。

Bethany のデザイナーと比べて、次の違いがある。

- **配置の仕方が違う。** LCL は座標(Left・Top・Width・Height)と Align・Anchors で置く。Tokotachi は親に 1 つ付くレイアウト
  (BoxLayout・GridLayout・PlaceLayout。ADR 0017)に入れる。デザイナーは座標ではなく「どのレイアウトのどこに入れるか」を編集する。
- **Tokotachi は自分で描くライブラリで、画面なしで描いて画像にできる**(SDL の offscreen。リファレンスのサンプルの一覧の画像はこの方法で撮っている。ADR 0038)。
  Bethany は、拡張から LCL を動かすのが難しいので、キャンバスを HTML で似せて描き、配置の計算を TypeScript に移した(Bethany ADR 0036)。
- **生成するのは C++ だけ**(Tokotachi に Python のバインディングは無い)。

配布は VS Code の Marketplace を想定する。Marketplace は公開のたびに複数のウイルス対策ソフトと、隔離した仮想マシンでの実行で自動の検査をする。
実行ファイルを含む拡張(OS ごとの .vsix)は認められていて、広く使われている拡張にも例が多いが、署名の無い実行ファイルは
ウイルス対策ソフトに誤って検知されることがある(Marketplace の検査でも、利用者の環境でも)。

## 検討した選択肢

### 置き場所

- 選択肢A: 別のリポジトリ。API の変更とデザイナーの更新が別々のコミットになり、ずれやすい。
- 選択肢B: 本リポジトリの `designer/`。API の変更と同じコミットでカタログ・コード生成を直し、確かめられる(Bethany ADR 0035 と同じ理由)。

### キャンバスの描き方

- 選択肢A: Bethany と同じく HTML で似せて描き、Box・Grid の配置と文字の大きさの計算を TypeScript に移す。
  拡張だけで動くが、見た目は近似で、配置の計算を実物と照らし合わせ続ける必要がある。
- 選択肢B: Tokotachi で描く小さなプログラムを OS ごとの実行ファイルにして .vsix に入れる。見た目も配置も実物と同じ。
  OS ごとの .vsix が要り、実行ファイルの誤検知の心配がある。
- 選択肢C: Tokotachi を Emscripten で WebAssembly にし、拡張(Node.js)の中で描く。見た目も配置も実物と同じで、実行ファイルを含まず、
  .vsix は 1 つで済む。依存ライブラリの WebAssembly へのビルドと、OS ごとに分けている部分(フォントの探し方など)の WebAssembly 版が要る。
  動くかどうかは試していない。

### 生成するクラスの形

- 選択肢A: ウィンドウを継承する(`class MainWindow : public tokotachi::Window`)。C++Builder・Bethany と同じ形。
- 選択肢B: Qt の uic のように、部品を組み立てる別のクラスを生成し、利用者のクラスがそれを持つ。

## 決定

**本リポジトリの `designer/` に、VS Code の拡張 + 画面の定義ファイル(JSON)+ コード生成の形でデザイナーを作る。
キャンバスは選択肢C(WebAssembly にした Tokotachi で描く)を目指し、生成するクラスはウィンドウを継承する(選択肢A)。**

- **キャンバス**:
  - 拡張の中で WebAssembly の Tokotachi が定義ファイルから画面を組んで描き、画像と、各部品の位置を返す。
    Webview は画像を表示し、選択の枠・入れる場所の印・ドラッグ中の表示だけを HTML で重ねる。
  - 定義ファイルの形式・カタログ・コード生成(下の順序の 1〜3)と並行して、**WebAssembly で 1 つの画面を描けるかを先に小さく試す**。
  - 試した結果が難しければ、**選択肢A(Bethany と同じく HTML で似せて描く)にする。実行ファイルは配らない**(選択肢B は採らない)。
  - 拡張と描画の部分のやり取りの決まりは、どちらの方式でも同じ形にして、方式を変えても拡張・Webview を作り直さずに済むようにする。
  - **試作の結果(2026-10-10、`spike/wasm/`)**: 描けた。WebAssembly で進める。
    - Emscripten 6.0.12 で、依存ライブラリ 6 つと Tokotachi 本体を、ソースを OS ごとに分けることなくビルドできた
      (手を入れたのは、CMake の探す場所と、フォントの探し方だけ)。SDL は offscreen のドライバを使う。
    - Node.js 24 の中で、一覧・木・Splitter・入力欄・ボタンの画面を描き、**MinGW の実物と 1 画素も違わない**画像が得られた
      (日本語・中国語・韓国語・アラビア語の右から左を含む)。部品の位置(ウィンドウの座標)も取り出せた。
    - 時間は、最初の描画が約 150 ms(フォントの読み込みを含む)、プロパティを変えての描き直しと、画面の組み直しがどちらも 1 回約 8 ms(PNG にするまで)。
    - 大きさは .wasm が約 2.7 MB、JS が約 190 KB。
    - スレッドは使わない設定でビルドした(SDL もスレッドなし)。キャンバスでは Task・別のスレッドからの post は使わない。
- **Bethany のデザイナーから流用するもの**(複製して Tokotachi に合わせて直す。コードは共有しない):
  - パッケージの分け方(core・codegen・cli・extension・webview)と依存の向き、道具(pnpm・TypeScript・ESLint・Prettier・Vitest・esbuild・Vite)。
  - マーカーで囲んだ区間だけを書き換えるコード生成。
  - 定義ファイルを唯一の正とし、編集をコマンドで表し、Undo を VS Code に任せる編集のしくみ。拡張と Webview の通信の骨組み。
  - 定義ファイルの形式を Zod で決めて、型と JSON Schema を導出するやり方。
  - プロジェクトファイルとプロジェクトのビュー(Bethany ADR 0065)、日本語・英語への対応。
- **流用しないもの**: 定義ファイルの形式(配置の表し方が違う)、LCL のカタログの取り出し、LCL の配置の計算と実測の照合、
  部品ごとに見た目を似せる React の部品、Python のコード生成。
- **カタログ**(部品・プロパティ・ハンドラの一覧)は公開のヘッダから取り出す。ヘッダのコメントは Doxygen の形になっている(ADR 0038)ので、
  Doxygen の XML 出力を使い、説明をインスペクタにも出す。
- **名前から部品を作るしくみ**(クラス名から部品を作る・プロパティ名で値を入れる)は、ライブラリの API には加えず、
  キャンバスの描画の部分の中に、カタログから生成した対応表として持つ。
- **進める順序**:
  1. 定義ファイルの形式([docs/designer/dsl-spec.md](../designer/dsl-spec.md))・コード生成・カタログの設計。
     **並行して WebAssembly の試作**(`spike/` に置く)。
  2. カタログの取り出し。
  3. コード生成と CLI(生成したコードを Tokotachi でビルドして動くことを確かめる)。
  4. キャンバスの描画の部分(WebAssembly。難しければ HTML)。
  5. VS Code の拡張とデザイナーの画面。

## 影響

- 本リポジトリに Node.js・TypeScript のコードが加わる。`designer/` の外のビルド(CMake)は Node.js に依存しない。
- WebAssembly にする場合、依存ライブラリのビルドに Emscripten の環境が加わる(deps/ の対象が 1 つ増える)。
  フォントは、拡張が OS のフォントのファイルを渡して読ませる(実物と同じフォントで描くため)。
- 公開のヘッダを変えたら、カタログを取り出し直す。カタログとヘッダが食い違っていないかを検査するしくみを、カタログの取り出しとあわせて用意する。
- キャンバスには拡張に入れた版の Tokotachi が入る。利用者のプロジェクトが違う版を使うと、見た目が少しずれることがある。
- 利用者が自分で作った部品は描けないので、仮の枠で表示する。
