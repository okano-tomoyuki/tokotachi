# 0017. 配置はウィジェットに 1 つだけ付けるレイアウトが決め、測る・置くの 2 段階で、描画の前にまとめて行う

- 状態: 承認
- 日付: 2026-10-04

## 背景

これまでは配置の仕組みが無く、利用者がウィンドウの大きさの変化に合わせて子の `bounds` を自分で計算していた。

参考にしたもの:

- bethany(LCL): 完全な自由配置(と Align・Anchors)。
- cpp_tk(Tk): place・grid・pack の 3 つのジオメトリマネージャー。子の側がマネージャーを選ぶため、同じ親の中で pack と grid を
  混ぜると、互いに相手の配置を直し合って止まらなくなる、という有名な問題がある。
- Qt: レイアウトのオブジェクトを親に付ける(QBoxLayout・QGridLayout)。
- WPF・Flutter: 測る(子が望む大きさを返す)・置く(親が大きさを決める)の 2 段階。

いずれのマネージャーにも当たるものを用意したい。一方で、親が子のジオメトリを決め、子はそれに従う形が破綻が少ない。

## 検討した選択肢

1. レイアウトの持たせ方: (A) 別の Object としてウィジェットに付ける / (B) Box・Grid 自体を入れ物のウィジェットにする。
2. 子ごとの設定(行・列・伸びる割合): (A) レイアウトが持つ(`grid->add(w, 0, 1)`) / (B) 子のプロパティとして持つ(WPF の `Grid.Row`)。
3. 入れ子: (A) 入れ物のウィジェットを介す / (B) レイアウトの中に直接レイアウトを入れる。
4. pack に当たるもの: Box だけ / Dock も最初から用意する。

## 決定

1〜3 はいずれも (A)、4 は Box だけにする。

### レイアウトの付け方

- **レイアウトは Object の派生クラスで、ウィジェットに 1 つだけ付く**(`new gui::BoxLayout(panel)`。ウィジェットが所有する)。
  1 つの親に 1 つのレイアウトしか無いので、Tk のように同じ親の中で配置の仕方が混ざることが構造上起きない。
  - `widget->layout` は読み取り専用のプロパティ。レイアウトを作ると付き、2 つ目を作ると古いものは破棄され、`delete` すると外れる
    (付け方・外し方を 1 通りにする)。
  - レイアウトの無いウィジェットは自由配置(子の `bounds` を利用者が決める。bethany と同じ)。
- **レイアウトが管理するのは、付いているウィジェットの子だけ**。子でないウィジェットを `add` すると子にする(親を付け替える。
  [ADR 0018](0018-reparenting.md))。当初は警告を出して無視していたが、サンプルを書いていて実際に踏んだため改めた。
- レイアウトが管理する子の `bounds` はレイアウトのもので、代入しても次の配置で上書きされる。
- 子ごとの設定は、引数を取るのでメソッドにする(`add(w, stretch, align)`、`set_column_stretch(column, n)`。[ADR 0013](0013-api-style-properties-and-handlers.md))。
- 入れ子は、行・列ごとに入れ物のウィジェット(`gui::Widget`)を作り、それにレイアウトを付けて親のレイアウトに加える。

### 大きさの手がかり

- `preferred_size`(読み取り専用): 望む大きさ。ウィジェットが `compute_preferred_size()` で決める。レイアウトを持つウィジェットは、
  レイアウトが子から集めた大きさ。`minimum_hint` 以上 `maximum_size` 以下に収める。
- `minimum_size`・`maximum_size`: 利用者が決める最小・最大(既定は 0 と無制限)。
- `minimum_hint`(読み取り専用): レイアウトが縮めてよい最小の大きさ。`minimum_size` と、ウィジェットが `compute_minimum_size()` で
  決める値の大きい方。Label・ボタンの類は文字が切れないよう望む大きさを最小とし、LineEdit は横だけ狭くできる(スクロールする)。
- 隠れている子は配置しない(大きさ 0 として詰める)。

### 配置の手順

- **測る(下から上)**: レイアウトは子の望む大きさ・最小の大きさを集め、余白(`margins`)と間隔を加えて自分の大きさを決める。
- **置く(上から下)**: 実際の大きさを受け取り、子の `bounds` を決める。余る長さは伸びる割合(stretch)に応じて分け
  (最大を超えた分は他の伸びる項目へ回す)、どの項目も伸びなければ余りは残す。足りない長さは、各項目を最小の大きさまで、
  望む大きさとの差に応じて縮める。
- **配置のやり直しは印を付けるだけにし、描画の直前に上から下へまとめて行う**(`request_layout()`)。子の望む大きさが変わると
  根まで印を付け、大きさが変わったウィジェットは自分に印を付ける。1 回の操作で何度も配置し直すことと、配置の途中の依頼で止まらなくなる
  ことを避ける(配置の結果を受けたハンドラが依頼した分も、上限を設けて同じ描画の前に済ませる)。すぐに結果を読みたいときは
  `apply_layout()` を呼ぶ。
- **子の辺はピクセルの整数に揃える**(分数の倍率でも境界がにじまないように)。[ADR 0008](0008-coordinate-spaces.md) で保留していた
  「スナップをどの層で行うか」は、配置の層で行うことにした。
- レイアウトが決めた `bounds` は、プロパティの変更として知らせる([ADR 0016](0016-property-binding.md))。結んだ変数にも伝わる。
- レイアウトを持つウィンドウは、その最小の大きさより小さくできない(SDL3 の最小の大きさに伝える)。

### 用意するレイアウト

| cpp_tk | レイアウト | 内容 |
|---|---|---|
| place | `PlaceLayout`(と、レイアウト無しの自由配置) | 位置・大きさを、絶対の値と親の大きさに対する割合の和で決める。アンカーで子のどの点を合わせるかを選ぶ |
| pack | `BoxLayout` | 横または縦に並べる。項目ごとの伸びる割合と直交する向きのそろえ方、固定の空き・伸びる空き、間隔、余白 |
| grid | `GridLayout` | 行と列、またがる配置、行・列ごとの伸びる割合と最小の大きさ、セルの中でのそろえ方(sticky に当たる) |

pack で `side` を混ぜる使い方は Box の入れ子で表す。必要になったら Dock(WPF の DockPanel)を加える。

利用者が独自のレイアウトを作るときは、`Layout` を継承し、`compute_preferred_size`・`compute_minimum_size`(余白を除いた大きさ)・
`arrange`(余白を除いた矩形)・`widget_removed` を実装する。

## 影響

- GridLayout は、項目が無く最小の大きさも決めていない行・列を大きさ 0 とし、間隔も入れない。
- そろえ方は `Align`(START・CENTER・END・FILL)に統一し、Label の文字のそろえ方にも使う(当初は Label に別の `Alignment` があった)。
  「左・右」ではなく「始め・終わり」とするのは、右から左へ書く言語に対応したときに意味が変わらないようにするため。
