# 0022. ポップアップは Popup(Window の派生)とし、開いているメニューは Application がまとめて扱う。ComboBox・Menu・ツールチップをその上に作る

- 状態: 承認
- 日付: 2026-10-04

## 背景

[ADR 0011](0011-popups-as-child-windows.md) で、メニュー・ドロップダウン・ツールチップは SDL3 の `SDL_CreatePopupWindow` で、
親のウィンドウに相対的なポップアップとして作ると提案した。それを実装し、ComboBox・メニュー・ツールチップを作る。

SDL3 のソースで確かめたこと:

- 親はポップアップでもよい(サブメニューのような入れ子が作れる)。位置は親からの相対で、画面からはみ出すときは既定で収まるよう調整される。
- メニューの種類(`SDL_WINDOW_POPUP_MENU`)は、表示すると自動でキーボードのフォーカスを得る。ツールチップの種類(`SDL_WINDOW_TOOLTIP`)は入力を受けない。
- Wayland では、外側を押すとコンポジタがポップアップを閉じ、SDL3 は「閉じる要求」(`SDL_EVENT_WINDOW_CLOSE_REQUESTED`)を送る。
  Windows・X11 には、外側を押したら閉じる仕組みが無い。
- 親のウィンドウが破棄されると、子のポップアップも OS ごと破棄される。
- offscreen のビデオドライバは、ポップアップに対応しない。

## 決定

### Popup

- **`Popup` は `Window` の派生クラス**とし、中身はふつうのウィジェット・レイアウトで作る。持ち主のウィジェット(`owner_widget`)を基準に、
  `open(anchor, size, placement)` で開く(`BELOW`・`RIGHT`・`AT`)。OS のウィンドウは最初に開くときに、持ち主のウィジェットのウィンドウの子として作る。
- 持ち主のウィジェットが所有者になる(一緒に破棄される)。基準と持ち主が違うとき(Menu)は、所有者を別に指定できる。
  ポップアップは親のウィンドウより先に破棄する(OS が子のポップアップを消すため)。
- `close()`(`Window::close` を仮想にした)は、そのポップアップから後に開いたポップアップも閉じ、`on_closed` を呼ぶ。
  ポップアップが閉じても、アプリケーションは終わらない(表示されているウィンドウの数え方からポップアップを除く)。
- **開いているメニューの種類のポップアップは、Application が開いた順に持つ**。
  - ポップアップの外側でボタンが押されたら、すべて閉じ、押したことは外側のウィンドウに送らない(Windows・X11 のため。Wayland はコンポジタが閉じる)。
  - キー・文字の入力は、OS がどのウィンドウにフォーカスを与えたかによらず、一番上のポップアップへ送る。
- 隠したポップアップが画面に残ることがあった(WSLg)ため、**Wayland ではポップアップを閉じるときに SDL3 のウィンドウを破棄し**、
  次に開くときに作り直す。Windows・X11 は隠すだけにする。
- **ポップアップに対応しないビデオドライバ**(offscreen)では、枠の無い通常のウィンドウを、親の位置 + 相対の位置に置いて代わりにする
  (画面の無い CI でテストを動かすため)。Wayland はポップアップに対応するので、この代わりは使わない(絶対の位置を指定できないことと矛盾しない)。

### ComboBox

- `items`(文字列の一覧)・`current_index`(-1 なら選んでいない。範囲の外は -1)・`current_text`(読み取り専用)・`placeholder_text`・`on_change`。
- 押すと、項目の一覧(内部の `PopupList`)をポップアップで下に開く。一度に見せるのは 10 項目までで、それ以上は ScrollArea でスクロールする。
- 閉じているときは ↑↓・Home・End で選択を変え、Space・Enter・Alt+↓・F4 で開く。開いているときは ↑↓・Page Up/Down・Home/End で動かし、
  Enter で決め、Esc で閉じる。ポインタを乗せた項目を強調し、クリックで決める。

### Menu

- `Menu` と `MenuItem` は Object の派生クラス(MenuItem の所有者は Menu、サブメニューの所有者は親の Menu)。
  `MenuItem` は `text`・`shortcut_text`(表示だけで、キーは割り当てない)・`enabled`・`submenu`(読み取り専用)・`on_click`。
  (後に [ADR 0027](0027-actions-shortcuts-and-menu-bar.md) で、項目は Action で表すように変えた。)
- `add_item`・`add_separator`・`add_submenu`、`popup(anchor_widget, at)`(右クリックの位置などに開く)・`close`。
- ↑↓(区切りと無効な項目を飛ばす)・Enter で選ぶ・→ でサブメニューを開く・← でサブメニューを閉じる・Esc で閉じる。
  サブメニューの項目にポインタを乗せると開く。
- 項目を選ぶと、**メニューをすべて閉じてから** `on_click` を呼ぶ(ハンドラがダイアログを開くなどしてもよいように)。
- メニューを破棄するときは、サブメニューを先に破棄してから自分のポップアップを破棄する。

### ツールチップ

- `Widget::tooltip`(文字列のプロパティ)。ポインタを 600 ミリ秒止めると、ポインタの少し下にツールチップの種類のポップアップで出す。
  ポインタが別のウィジェットへ移る・ボタンを押す・キーを押す・ウィンドウから出ると消す。

## 影響

- [ADR 0011](0011-popups-as-child-windows.md) を承認にする(実装の詳細は本 ADR)。
- WSLg(Wayland)で、本物のポップアップ(xdg_popup)として開けることを確かめた。キーボードでの操作・外側のクリックで閉じることは、
  テストで(SDL のイベントを作って Application に渡して)確かめた。実機の GNOME・KDE での確認は今後。
- **WSLg の既知の制限**: ComboBox の一覧は、クリックで開いても、ポインタが動くまで画面に映らない
  (トレースでは、ポップアップの表示も描画も済んでいる)。描き直す・親のウィンドウも描き直す・ボタンを離したときに開く、を試したが変わらなかった。
  Weston(WSLg のコンポジタ)の、出力が割り当てられていない面は commit しても再描画されない不具合
  ([weston MR 1123](https://gitlab.freedesktop.org/wayland/weston/-/merge_requests/1123))と同じ種類とみて、ライブラリ側では対処しない。
  実機の GNOME・KDE で確かめる。
- メニューバー(ウィンドウの上の横並びのメニュー)、キーの割り当て(ショートカット)、チェックのある項目は対象外。
