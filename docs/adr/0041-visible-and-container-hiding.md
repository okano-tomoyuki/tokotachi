# 0041. 入れ物が自分の都合で子を隠すときは visible を変えず、内部の印で隠す

- 状態: 承認
- 日付: 2026-10-11

## 背景

`visible` は利用者が決める「表示するか」だが、次の 3 つの入れ物は、自分の都合で子の `visible` を書き換えていた。

| 入れ物 | 子を隠す都合 |
|---|---|
| ToolBar | 幅に収まらない項目を隠す(並べ直すたびに、収まる部品を `visible = true` に戻す) |
| Splitter | たたんだ区画の部品を隠す(並べ直すたびに、たたんでいない区画の部品を `visible = true` に戻す) |
| TabWidget | 選んでいないタブのページを隠す(選ぶと `visible = true` にする) |

このため、ToolBar の部品・Splitter の区画の部品に `visible = false` を設定しても、次に並べ直したときに戻ってしまい、効かなかった。
デザイナーで visible を外してもキャンバスで消えないことから見つかった(キャンバスは生成したコードと同じ操作を実行するので、
実行したアプリでも同じく効かない)。また、利用者が `visible` を読んでも、自分が設定した値なのか入れ物の都合なのかが区別できなかった。

## 検討した選択肢

- 選択肢A: デザイナーだけで対処する(この 2 か所の子の visible を警告にする・書けなくする)。ライブラリの不具合は残る。
- 選択肢B: 入れ物が、利用者の `visible` を読んで尊重する(隠した部品を飛ばす)。ただし入れ物が自分で書き換える限り、
  利用者の値と入れ物の都合を区別できないので成り立たない。
- 選択肢C: Widget に、`visible` とは別の内部の印「親が隠している」を持たせる。入れ物はこの印だけを変え、
  描く・配置する・クリックやフォーカスを受けるかは、両方を見て決める(Qt の「明示的に隠した」と「親の都合で隠れている」の区別に近い)。

## 決定

**選択肢C。** 利用者の `visible` は、ライブラリが変えない。

- Widget に内部の印(`hidden_by_parent_`)を加える。描く・配置する・ヒットテスト・フォーカスの対象・`showing` は、
  「visible で、親に隠されていない」(`displayed()`)で決める。印は `detail::WidgetAccess::set_hidden_by_parent` からだけ変える(公開の API は増やさない)。
- `visible` は利用者の値のまま、`showing` は「実際に表示されるか」になる。入れ物の都合で隠れているかは `showing` で分かる。
- 入れ物ごとの、利用者が隠した子の扱い:
  - **ToolBar**: `add_widget` の部品を `visible = false` にすると、場所を取らない。それによって端に来た・続いた区切りも置かない
    (区切りは、前と後ろの両方に並べる項目があるときだけ置く。これは部品を隠さないときも同じで、末尾の区切りは置かない)。
  - **Splitter**: 区画の部品を `visible = false` にすると、その区画は場所も境目も取らない。大きさは覚えていて、戻すと元の大きさで出る
    (`sizes` は、部品を隠した区画について戻したときの大きさを返す)。境目の番号は、隠していない区画の並びで数える。
  - **TabWidget**: ページを `visible = false` にすると、そのタブを選んでもページを見せない。

## 影響

- 互換性: これまで `page->visible`・ToolBar の部品の `visible`・たたんだ区画の部品の `visible` を読んで「今見えているか」を調べていたコードは、
  `showing` を読むように直す(本リポジトリのテストを直した)。
- デザイナー: キャンバスでも、ToolBar の部品・Splitter の区画の部品の visible が効くようになった(生成したコードと同じ)。
- テスト: `tool_bar_keeps_user_visibility`・`splitter_hidden_pane_takes_no_space` を加え、TabWidget のテストに、利用者が隠したページを加えた。
