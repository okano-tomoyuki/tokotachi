# 0018. ウィジェットの親は付け替えられるようにし、レイアウトの add は子でないウィジェットを子にする

- 状態: 承認
- 日付: 2026-10-04

## 背景

[ADR 0015](0015-object-ownership.md) で「所有者の付け替えは今は扱わない」とし、[ADR 0017](0017-layout.md) のレイアウトは
「付いているウィジェットの子だけを管理し、子でないウィジェットを `add` すると警告を出して無視する」とした。

サンプルを書いていて、ボタンをウィンドウを親にして作ったまま行の入れ物のレイアウトに `add` してしまい、行が表示されないという
落とし穴を実際に踏んだ。警告を出しても、利用者にとっては「add したのに入らない」ことに変わりはない。

## 決定

- **`Widget::parent` を書き込めるプロパティにする**。代入すると親を付け替える。
  - 表示のツリー(`children`)と所有者(`owner`)が一緒に移る(ウィジェットでは親と所有者が常に一致する)。
  - 移る前の親のレイアウトから外れ、両方の親に配置のやり直しを依頼する。
  - 移る前のウィンドウが持つ、自分と子孫への参照(フォーカス・ホバー・マウスの捕捉)を外す。別のウィンドウへ移ったときは、
    倍率が違うかもしれないので、自分と子孫に `scale_changed` を送る。
  - ウィンドウは付け替えられない。自分の子孫を親にすることはできない(循環)。どちらも無視して標準エラーに警告を出す。
  - nullptr にすると親も所有者も無くなる(利用者が破棄する)。
- 所有者の付け替えは、内部では `Object::change_owner` で行う。ウィジェット以外の Object の `owner` は、これまでどおり読み取り専用。
- **レイアウトの `add` は、子でないウィジェットを子にする**(親を付け替える。Qt の addWidget と同じ)。入れられないもの
  (ウィンドウ、付いているウィジェット自身やその祖先)だけを、警告を出して無視する。

## 影響

- ウィジェットを作るときの親を間違えても、レイアウトに入れれば正しい親に移る。
- 付け替えによって、結びつけ([ADR 0016](0016-property-binding.md))は変わらない(結びつきはプロパティの組で、親とは関係しない)。
