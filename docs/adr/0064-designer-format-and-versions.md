# 0064. デザイナーの定義ファイルの形式を固定し、移し替えの仕組みとライブラリの版との対応を決める

- 状態: 承認
- 日付: 2026-10-13

## 背景

デザイナーを 1.0 にする前に、利用者のファイルを長く読めるようにする約束と、ライブラリの版との関係を決める。今は次のとおり。

- 画面の定義ファイル(`*.ttui.json`)とプロジェクトファイル(`*.ttproj.json`)は、どちらも `format_version` が 1。1 以外の版のファイルは
  「対応していない」と言って開かない(古い版も新しい版も同じ扱い)。版ごとに移し替える仕組みは無い。
- Tokotachi の API で名前が変わったプロパティ・ハンドラは、読むときに新しい名前に読み替えている(`renamed.ts`。ADR 0059)。
- デザイナーのカタログは、あるライブラリの版から取り出したもの(`catalog.json` の `tokotachi_version`)。生成する `CMakeLists.txt` は
  その版を `find_package` で求める(ADR 0061)。どのデザイナーがどのライブラリの版に対応するかは、どこにも書いていない。
- 拡張は `package.json` の `"preview": true` で、Marketplace にプレビューとして出している。外すときの決まりは無い。

## 検討した選択肢

- 形式に項目を足すとき: 版を上げない(省略できる項目なら古いデザイナーも読める)/いつも版を上げる。版を上げないと、古いデザイナーは
  知らない項目で構造の検証に失敗し、理由の分からないエラーになる。いつも版を上げれば、古いデザイナーは「新しいデザイナーで作ったファイル」と
  はっきり言える。移し替えは項目を足すだけなら何もしない関数で済むので、いつも版を上げる。
- 移し替え: 開いたときに黙って新しい形式にする/開いたときに移し替え、保存したら新しい形式で書く(知らせる)/別のコマンドで移す。
  古いデザイナーで同じファイルを開く人がいると、保存した時点で読めなくなるので、移し替えたことを知らせる。
- デザイナーの版: ライブラリの版と同じにする/独立させ、大きい版だけそろえる。デザイナーはライブラリと関係のない修正・機能でも版を上げたいので、
  独立させる。ライブラリの大きい版の中はソースの互換があるので(ADR 0057)、大きい版だけそろえれば足りる。

## 決定

### 形式の固定と移し替え

- 1.0 で、`*.ttui.json`・`*.ttproj.json` の `format_version` 1 を固定する(今の仕様: docs/designer/dsl-spec.md・project-spec.md)。
- 形式を変えるとき(項目を足すだけでも)は `format_version` を 1 つ上げ、前の版から移す関数を用意する。読むときに、ファイルの版から今の版まで
  順に移し、それから検証する。移す関数は JSON のまま扱う(型の付いた形は今の版のものだけ持つ)。
- 古い版のファイルを開いたら、移し替えたことを情報として出す(「保存すると形式 N で書き出す。古いデザイナーでは開けなくなる」)。
  保存すると今の版で書き出す。
- 今の版より新しいファイルは開かず、「新しいデザイナー(形式 N)で作ったファイル。デザイナーを更新する」と出す。
- Tokotachi の API の改名(`renamed.ts`)は形式の版とは別に扱う。古い名前はいつまでも読み替える(1.0 からは、ライブラリの改名は非推奨を経て
  大きい版で行う。ADR 0057)。

### ライブラリの版との対応

- デザイナーの版はライブラリと独立させるが、**大きい版はそろえる**(デザイナー 1.x は Tokotachi 1.x 用)。
- デザイナーの各版が対象にするライブラリの版は、カタログを取り出した版(major.minor)とし、次のところに出す。
  - 拡張の CHANGELOG の各版(「Tokotachi 1.2 用」)と README。
  - プロジェクトの設定画面。
  - 生成する `CMakeLists.txt` の `find_package(tokotachi <major.minor> REQUIRED)`(1.0 からは、同じ大きい版でそれ以上の版を受け付ける。
    古いライブラリでは configure で止まるので、ずれに気づける)。
- 対応の一覧を docs/designer に置き、手引きの「版と互換の約束」からも引けるようにする。

### プレビューの印

- 拡張の版が 1.0 より前なら `"preview": true`、1.0 からは外す。公開のジョブが、版と印が合っているかを確かめる。
- デザイナー 1.0 はライブラリ 1.0 と一緒に出す(印を外すのは、その版を上げるコミット)。

## 影響

- 移し替えの仕組みは、今は移す関数が無い(版 1 だけ)。仕組みとテストは、版 0 や版 2 の仮のファイルで確かめる。
- 生成したコード(区間の外)は、形式を上げても直さない(利用者のもの)。
- ライブラリの大きい版を上げるときは、デザイナーの大きい版も上げる。

## 実装

- 移し替え: `packages/core/src/format.ts` の `migrateFormat`。`parseDocument`・`parseProject` が、構造の検証の前に呼ぶ。移す関数の表は
  `TTUI_MIGRATIONS`・`TTPROJ_MIGRATIONS`(今は空)。仮の表で、順に移すこと・新しい版を開かないこと・移す関数の無い古い版を途中まで
  直さないことをテストした。
- プロジェクトの設定画面の「コード生成」の欄に、対象の Tokotachi の版を出す。
- `designer/tools/release/check.mts`(`pnpm release:check`。`pnpm check` の中で動く)が、プレビューの印と大きい版を確かめる。
- 版の対応の表は docs/designer/README.md の「版と互換」。
