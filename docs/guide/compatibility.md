# 版と互換の約束 {#compatibility}

[TOC]

Tokotachi の版の付け方と、版を上げたときに利用者のコードがそのまま使えるかの約束です(設計の判断は
docs/adr/0057・0061)。変更の一覧はリポジトリの `CHANGELOG.md` にあります。

## 版の付け方

版は `大きい版.小さい版.修正の版`(例: `1.2.0`)です。

| 版 | 1.0 から | 0.x の間 |
|---|---|---|
| 大きい版 | 利用者のコードを壊す変更を入れる | 0 のまま |
| 小さい版 | 機能を足す(利用者のコードはそのままコンパイルできる) | 利用者のコードの修正が要る変更も入る |
| 修正の版 | 不具合を直す | 不具合を直す |

コンパイル時の版は `TOKOTACHI_VERSION_AT_LEAST(1, 2, 0)`、実行時に読み込まれたライブラリの版は `tokotachi::version()` で調べます。

## ソースの互換(1.0 から)

**大きい版が同じなら、版を上げても利用者のコードはそのままコンパイルできます。**

- 名前を変える・消すときは、すぐには消さず、非推奨の印を付けて残します。使うとコンパイルの警告に代わりの名前が出ます
  (リファレンスには「非推奨」と出ます)。消すのは次の大きい版です。
- 約束に含めないもの:
  - 名前空間 `tokotachi::detail` の中のもの(ライブラリの内部です。共有ライブラリの外にも見せていません)。
  - リファレンスに「内部」と書いたもの。
- `CMake` のパッケージは、1.0 からは「大きい版が同じで、求めた版以上」を受け付けます(`find_package(tokotachi 1.2)` は 1.5 でもよい)。
  0.x の間は小さい版まで同じものを求めます。

## 共有ライブラリの互換(ABI)

共有ライブラリ(`libtokotachi.so`・`libtokotachi.dll`)を差し替えたときに、作り直さずに動くかの約束です。

- 公開のクラスは中身を隠しているので(pimpl)、ライブラリの中の変更では ABI は変わりません。
- ABI が変わるのは、公開のクラスにプロパティ・ハンドラ・仮想関数を足したときなどです。その版では Linux の共有ライブラリの名前(SONAME)を
  変えるので、古いプログラムが新しいライブラリを誤って読むことはありません。
  - 1.0 から: `libtokotachi.so.<大きい版>.<ABI を最後に変えた小さい版>`(1.1・1.2 で ABI が変わらなければ `libtokotachi.so.1.0` のまま)。
  - 0.x の間: 小さい版ごとに変わります(`libtokotachi.so.0.2`)。
- Windows の DLL は名前に版を入れません。exe の隣に、その exe を作ったときの版の DLL を置いて配ってください。
- C++ の ABI はコンパイラと標準ライブラリにも依存します。ライブラリと同じ系統のコンパイラ(Windows は MSYS2 の MINGW64 の GCC)で
  使ってください。配布するパッケージには、作った環境を書いた `BUILD_INFO.txt` が入っています。

## 派生してよいクラス

派生してよいのは次のクラスです(@ref custom_widgets_guide)。protected の仮想関数のうち、手引きに挙げた「上書きする口」も互換を守ります。

- `Object`・`Widget`・`Window`・`Dialog`・`PaintBox`
- 拡張のための基底: `ButtonBase`・`RangeBase`・`Layout`・`ItemModel`
- 具体的な部品(`Button`・`LineEdit`・`ListView` など)

派生できないもの:

- `Canvas`(ライブラリが作って渡します)。
- `TextInputBase`・`ItemView`・`Item`(ライブラリの中だけの基底。型としては使えます)。
- ライブラリが作って返すクラス(`Tab`・`Column`・`SplitterPane`・`TreeItem` など。`final` が付いています)。

## 例外

- ライブラリは例外を投げません(メモリが足りないときの `std::bad_alloc` を除きます)。
- ハンドラの中で起きた例外は、ハンドラの中で捕まえてください。ハンドラの外へ出たときの振る舞いは決めていません。

## デザイナーとの対応

- デザイナー(拡張)の大きい版は、ライブラリの大きい版と同じです(デザイナー 1.x は Tokotachi 1.x 用)。各版が対象にするライブラリの版は、
  拡張の CHANGELOG とプロジェクトの設定画面に出ます。生成する `CMakeLists.txt` は、その版を `find_package` で求めます。
- 生成したコードが使う API と、生成したファイルの印(再生成で置き換える区間)は、デザイナーの大きい版の中で守ります。
- 定義ファイル(`*.ttui.json`・`*.ttproj.json`)は、古い形式も読み、保存すると新しい形式で書きます。新しいデザイナーで作ったファイルは、
  古いデザイナーでは開けません(デザイナーの更新を促します)。
